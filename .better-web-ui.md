## Design Context

### Users
Physicians and clinical reviewers using an AI-assisted case-taking tool in a focused workflow. The job is to capture a patient narration, inspect traceable structured findings, and make a human decision about what is reliable. The interface must make clear that it is decision support and never a diagnosis system.

### Brand Personality
Calm, trustworthy, transparent. The language is neutral and clinical, with reassurance coming from evidence and clear review states rather than promotional claims.

### Aesthetic Direction
Light-first clinical workspace with cool slate surfaces, a restrained teal accent, generous whitespace, soft elevation, and subtle motion. The experience should feel like a focused clinical instrument, not a dashboard: one primary task per view, strong hierarchy, and progressive disclosure. Support dark mode with the same semantic tokens.

### Implementation Defaults
The existing project is a Python clinical NLP backend with Pydantic schemas and a Streamlit prototype. The new frontend baseline is a dependency-free `index.html` that can call the backend contract when available and falls back to a local mock for development. The visual system is implemented with CSS variables and semantic HTML; no frontend framework is assumed for this first integration surface. Future framework work should preserve the backend's PatientRecord concepts and evidence offsets.

### Design Principles
1. Lead with the patient narration task, not navigation or metrics.
2. Make every AI output traceable to source text and label uncertainty plainly.
3. Use hierarchy, spacing, and typography before color or decoration.
4. Keep one obvious primary action per state and make recovery paths explicit.
5. Treat physician review as the final authority; never imply diagnosis or autonomous clinical judgment.
